Quick start

Get Raemote running

Five minutes: install the server on the computer that runs your apps, install the app on your phone, scan one QR code.

1 Before you start

Will your app work? Check in ten seconds. On the computer that runs it, open http://localhost:<port> in a browser — the same address you'd use locally. If the page loads, Raemote can reach it too.

From a terminal, that's one line:

curl -I http://localhost:3000
What that check is really doing is exactly what Raemote does when it looks for apps: it asks each local port for its page and keeps the ones that answer with a real web page. So if it loads for you, Raemote will find it.

Raemote speaks plain HTTP — what a lot of self-hosted software serves out of the box. An app you've already put behind HTTPS with a certificate won't be reachable yet; that's the next thing we're building.

Nothing loading yet? That's fine — you can also add one by hand later with raemote apps add <name> <port>.

You'll also need

  • A Mac (Apple Silicon or Intel) or a Linux machine (x86_64 or arm64 — a Raspberry Pi is fine) that runs the web apps you want to reach.
  • An iPhone. The app targets iOS 27 or later.
  • Nothing exposed to the internet: Raemote keeps everything on your machine and hands it only to devices you paired.

Don't have any apps running yet? A dev server is enough — start anything that serves a web page and Raemote will show it.

2 Install the server

curl -fsSL https://github.com/raemote/raemote_cli/raw/main/install.sh | sh

On a network where GitHub is slow or blocked, use the Gitee mirror:

curl -fsSL https://gitee.com/pppkin/raemote_cli/raw/main/install.sh | sh

The installer puts raemote and raemoted in ~/.local/bin, installs a background service (launchd on macOS, systemd on Linux), starts it, and prints your pairing link.

Installer options and AI agents

Useful flags: --no-service, --bin-dir <dir>, --proxy <url>, --source gitee|github, --tag <tag>, --quiet.

For an AI agent or a script, --json writes one JSON object to stdout (including the node id and the pairing uri) and all progress to stderr, and exits non-zero on failure:

curl -fsSL https://github.com/raemote/raemote_cli/raw/main/install.sh | sh -s -- --json

Full contract: agent-install.md.

Prefer to read it first? Download install.sh, then run sh install.sh.

3 Install the phone app

Install Raemote from TestFlight on your iPhone (iOS 27+), then open it. There is no account to create and nothing to sign up for.

First launch shows a Safari “Not Secure Connection” page? That is Safari's own warning for the plain-HTTP loopback address Raemote uses inside the app — the hop to your computer is still end-to-end encrypted. Turn it off in Settings → Apps → Safari → Privacy & Security → Not Secure Connection Warning.

4 Pair your phone

On the computer that runs the server:

raemote pair

It prints a raemote:// link and a QR code. In the app, tap + and scan it — or paste the link with Manual Setup. You do this once per device.

The link is short-lived (five minutes by default) and can pair more than one device until it expires. Print a fresh one any time with raemote pair.

A longer-lived link, or pairing another device later

For a link that stays valid, pin a token and a long TTL in ~/.raemote/config.toml:

[bind]
token = "…64 hex characters…"
token_ttl_secs = 3153600000

then run raemote pair again. Treat that link as a secret: anyone holding it can pair. Or skip the server entirely — from an already paired device use … → Invite Device… in the app for a one-time code.

5 Use it

  • Your paired servers appear in the app; open one to see the apps raemoted found.
  • Tap an app to open it in Safari. Each app keeps its own origin, so logins and site data survive.
  • Open a second app and both stay running — the Recent row switches between them instantly, with page state intact.
  • The app refreshes itself when you return to it; tap … → Refresh Apps to scan again right away.

If an app never shows up, pin it by hand:

raemote apps add jellyfin 8096
raemote apps list

6 No phone handy

Pair this machine and browse the same apps from your desktop browser:

raemote connect '<link from raemote pair>'   # pair and open
raemote connect                              # reopen the last server

The app list is served on 127.0.0.1:7788 (move it with --port), and every app gets its own loopback port so its URLs and cookies behave exactly as they do on the server. --no-open skips launching the browser.

7 Day-to-day commands

CommandWhat it does
raemote statusis the service running, and how many apps were found
raemote doctorhealth check: daemon, permissions, config, discovery, relay
raemote discoverscan for apps right now (add --verbose to see what was skipped and why)
raemote apps listthe merged app list, with where each entry came from
raemote apps hide <name>drop a false positive (unhide restores it)
raemote devices listpaired devices, with names and node ids
raemote devices rename <id> "Living Room"give a device a readable name
raemote devices revoke <id>cut a device off immediately
raemote config set name "Mac mini"rename the server as paired devices see it
raemote logs -n 50recent activity (--follow to stream)
raemote restartrestart the service after a config change

8 If something looks wrong

Start here:

raemote doctor
SymptomFix
An app isn't listedraemote discover --verbose to see why it was skipped; then raemote apps add <name> <port>
The app can't be reachedcheck it answers http://localhost:<port>; HTTPS-only apps are not supported yet
The phone says it is not authorizedit was revoked, or the server's identity changed — run raemote pair again and re-scan
Doctor reports the relay unreachableon a restricted network, set an outbound proxy: raemote config set network.proxy http://host:port then raemote restart
Safari shows a “Not Secure” pagethat is Safari's loopback warning; switch it off in Settings as noted above
Nothing works after editing configraemote reload for most settings, raemote restart for network or identity changes

More in troubleshooting.md.

9 Remove it

curl -fsSL https://github.com/raemote/raemote_cli/raw/main/install.sh | sh -s -- --uninstall

Add --purge to also delete ~/.raemote — the server identity and the list of paired devices. Revoking a device from raemote devices is enough to cut off access without uninstalling anything.
